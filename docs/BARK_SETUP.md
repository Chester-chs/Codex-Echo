# iPhone 接入 Bark：关闭网页后也能收到 Codex 提醒

**简体中文** | [English](BARK_SETUP.en.md) · [返回首页](../README.md)

推荐使用 **Bark 云端提醒**。只需手机和浏览器，不需要配置 GitHub、购买服务器或域名。

| 方式 | 关闭网页后 | 使用要求 |
|---|---|---|
| **Bark 云端提醒（推荐）** | 仍可由云端发送到 iPhone，包括锁屏 | 先安装 Bark，在网页绑定自己的地址，允许手机通知 |
| 页面提醒 | **停止** | 需要保持页面开启并运行；切后台、锁屏可能暂停页面 |

页面提醒的“已开启”不等于已绑定 Bark，两处设置相互独立。想关闭网页后接收消息，请完成下面的 Bark 绑定。

## 第 1 步：安装 Bark 并允许锁屏通知

1. 在 iPhone App Store 搜索 **Bark**。可通过 [Bark 官方开源项目](https://github.com/Finb/Bark) 内的 App Store 链接核对应用。
2. 安装并打开 Bark，出现通知权限询问时选择允许。
3. 打开 iPhone「设置 → 通知 → Bark」，开启「允许通知」，勾选「锁定屏幕」。部分 iOS 版本也可从「设置 → App → Bark → 通知」进入。
4. 为方便首次测试，检查专注模式没有屏蔽 Bark、定时摘要没有延后它的通知。

**完成标志**：Bark 已安装，iPhone 允许它显示锁屏通知。

## 第 2 步：复制自己的 Bark 推送地址

回到 Bark，复制应用内显示的推送地址。通常形如：

```text
https://api.day.app/你的真实设备密钥
```

上面是格式示意，不能直接使用；请复制 **Bark 应用里的真实地址**。完整地址和其中的设备密钥都可以填。目前支持默认的 `api.day.app` 服务。

这个地址能用于给你的手机发消息，请勿公开，也不用发给网站作者。不要填写别人的地址。

**完成标志**：自己的真实地址已复制到剪贴板。

## 第 3 步：在网页绑定

1. 在 iPhone Safari 打开 **[Codex 回响](https://echo-radar.pages.dev/)**。
2. 页面向下滑，找到 **「手机云端提醒」**，点开它。它位于 Tibo 推文列表下方；不要选旁边的「页面提醒」。
3. 在 **「你的 Bark 推送地址」** 输入框粘贴第 2 步的地址。输入默认隐藏，可点「显示地址」核对。
4. 选择想接收的提醒：

| 设置 | 怎么选 |
|---|---|
| **重置公告** | 开启后提醒新收录的公开公告，不是你的个人账号额度通知 |
| **来源预测** | 开启后提醒有效、达到阈值的新来源预测，不是官方承诺 |
| **预测提醒阈值** | 40%–90%，每档 5%；例如 75%，表示达到或超过 75% 才符合条件 |
| **推送语言** | 选择「中文」或「English」；与网页显示语言可以不同 |

5. 点击 **「绑定并保存」**，等待完成。可以先保持默认：两类开启、60%、中文。

**完成标志**：看到「已绑定」、掩码设备信息或绑定成功提示。仅粘贴地址而未点击保存，不会订阅。显示「此浏览器未关联设备」时，这个浏览器还没有管理凭据。

## 第 4 步：关闭网页，做一次锁屏测试

1. 绑定后，在同一区域点击 **「发送测试通知」** 一次。
2. 页面提示测试已排队后，关闭网页并锁屏。通常一分钟左右发出，繁忙时可能更久。
3. 检查 iPhone 锁屏，寻找 **「Codex 回响 · 锁屏推送测试」**；英文推送标题是 **“Codex Echo · Push test”**。
4. 如需核对，重新打开网页，点击「刷新状态」查看最近推送状态。

**完成标志：手机锁屏上实际出现测试消息。**「等待发送」是排队中；「Bark 已接受」只说明 Bark 服务接受了请求，不保证锁屏已显示。测试每 10 分钟最多一次，不需要反复点。

测试不是重置公告，也不是预测信号。测试成功后即可等待新消息，无需保持网页或电脑运行。

## 修改设置与退订

- **调整设置**：回到「手机云端提醒」修改开关、阈值或语言，再点「保存提醒设置」。未保存的修改不会生效。
- **暂停云端提醒**：将两类提醒都关闭并保存。仅关闭网页不会暂停 Bark。
- **恢复**：重新开启需要的类型并保存。
- **退订**：点「退订并删除地址」，确认退订。将停止后续云端提醒并删除保存的地址；已经在发送的通知可能仍会到达。
- **换浏览器或清除数据**：再次粘贴同一个 Bark 地址绑定，可以恢复管理；之前浏览器的管理凭据会失效。不会因为一个浏览器显示“未关联”就自动停止原订阅。

## 没收到？按这个顺序检查

| 现象 | 处理方法 |
|---|---|
| 找不到提醒设置 | 往下滑到 Tibo 推文列表下方，展开「手机云端提醒」 |
| 按钮不能点 | 先粘贴自己的地址，等待正在处理的请求结束；测试可能处于 10 分钟冷却期 |
| 地址无效 | 从当前手机 Bark 重新复制；不要用教程示例、自建服务地址或别人的地址 |
| 测试排队但没到 | 等候片刻，点「刷新状态」；如果显示失败，核对地址和网络；结果不明不会自动重复发 |
| Bark 里有记录，锁屏没显示 | 检查允许通知、锁定屏幕、专注模式、定时摘要；打开 Bark 一次，再锁屏进行下一次允许的测试 |
| 测试成功，暂时没新提醒 | 首次绑定不补发历史。没有新收录的符合条件消息时保持安静；预测还需有效、达到阈值 |
| 收到重复消息 | 检查是否同时运行 GitHub 自助版或其他提醒服务，同一设备建议只保留一个来源 |
| 网页无法管理原订阅 | 使用原浏览器，或重新粘贴同一 Bark 地址绑定恢复管理 |

当前免费试运行最多 30 台设备，每台按 UTC 日期每天最多 20 次发送尝试，测试和重试也计入。配置即时队列后，发现新消息即提交发送；没有队列时仍每分钟调度。公开推文与确认事件每分钟检查，在同次任务内发送或入队；其他完整采集单独定时，不保证即时送达。上游、Bark、网络和手机设置都可能影响送达。

**记住：推荐 Bark；页面提醒需要保持页面运行。**

如希望自己运行提醒程序，可选用[独立的 GitHub 配置教程](GITHUB_BARK.md)，无需为了普通网页订阅完成它。

重置公告开关也包含来源明确公布的新重置计划，推送会标注「已公布重置计划」，不代表已经完成；无需重新绑定。预测阈值不影响计划提醒。

两阶段提醒：开启「重置公告」后，新计划公布时提醒一次；收录到来源明确确认完成的新消息后，再提醒一次。每条消息去重。仅到达计划时间不发送完成提醒；来源未确认时继续等待，不能据此判断个人账号额度。
