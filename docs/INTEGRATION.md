# 微信小程序接入：先免费开发

当前无需购买服务器或域名，也没有开通任何付费资源。AppID、环境 ID 和模板 ID 是标识，可以提供给协作者；AppSecret 不要发送到聊天。推荐的微信云开发方案不需要 AppSecret。

## 你现在先做这一小步

打开微信开发者工具，用你的小程序管理员微信登录，导入本项目的 `dist/weixin-project` 并填写自己的 AppID。点击顶部“云开发”，查看账号能否创建免费环境。**只选择明确显示 0 元的免费/体验选项；若只显示付费套餐，先停在这里。**记录环境 ID、免费到期日/额度，以及是否允许定时函数。

免费权益的规则存在不同入口版本：

- [CloudBase 定价页](https://www.cloudbase.net/pricing) 当前列出免费环境、每月 3,000 资源点、每次续期 6 个月等权益；这是体验额度，不是无限资源。
- [创建环境指南](https://docs.cloudbase.net/quick-start/create-env) 仍说明开发期免费、正式使用需付费。
- 不根据宣传页替你开通付费套餐，以你的实际控制台为准；暂不启用超额按量扣费或自动续费。

拿到 AppID 与环境 ID 后再做以下步骤。若免费环境不支持所需运行时、定时器或超时配置，保持本地免费开发，先确认可用选项，不自动买服务器。

## 1. 生成微信工程

`.env.local`：

```dotenv
VITE_WECHAT_CLOUD_ENV=你的环境ID
VITE_RADAR_API_BASE=/api
```

云环境 ID 只影响微信端；网页预览仍通过本机 `/api` 使用 Node 服务。`VITE_` 字段会打包进客户端，不能存密钥。

把 AppID 填入 `src/manifest.json` 中 `mp-weixin.appid`，然后运行：

```powershell
npm run check:release
npm run package:weixin
```

导入 `dist/weixin-project`，不要只导入子目录。生成目录不要手工修改业务代码；后续编译会覆盖它。

## 2. 创建数据库

在云开发控制台创建集合 **`pulse_radar`**，权限设为 **仅管理端可读写**。前端不直接读数据库，全部通过云函数鉴权。

该集合保存公开数据、预测版本、订阅设置、授权凭据去重和发送记录。用户记录按微信身份隔离，客户端不能指定收件人。当前适合小规模试用：一次最多处理 50 个用户，游标轮转；公开快照和单个用户文档各有 850 KB 保护上限，超过会报错而不是丢弃历史。达到上限前需升级为分页存储。

## 3. 上传两个云函数

选择已创建的环境，对 `cloudfunctions/pulseApi` 和 `pulseSync` 分别执行“上传并部署：云端安装依赖”。云端必须支持 **Node.js 20.19 或更高**，因为正文解析依赖要求 Node 20.18.1+。先不要启用公开 HTTP 访问或网页调用。

- `pulseApi`：仅用于微信客户端调用，建议超时 20 秒。
- `pulseSync`：仅用于受保护的控制台测试/定时任务，建议超时 180 秒；默认发送目标为体验版。
- 每函数使用单实例并发 1。发布前确认控制台按此配置，避免微信 SDK 的进程身份变量跨请求混用。
- `config.json` 已声明 `subscribeMessage.send` 云调用权限，需随 `pulseSync` 一起部署。

两函数的环境变量：

```text
WECHAT_APP_ID=你的AppID
WECHAT_TEMPLATES_JSON={}
WECHAT_MESSAGE_STATE=trial
```

先保持 `{}` 可以验证真实数据展示。模板配置前不会有可授权的消息模板。

`pulseSync` 还需要 **仅服务端保存** 的 `RADAR_SCHEDULER_SECRET`，随机生成至少 32 字符；不要填进 `VITE_`、源码、客户端或公开仓库。建议用密码管理器生成 64 字符。其作用是防止别人伪造定时器请求，触发额外采集或发送。

## 4. 初始化真实数据

在控制台测试 **pulseSync**，测试事件填：

```json
{"secret":"与服务端环境变量一致的值"}
```

成功应返回记录数与处理数。第一次建立历史基线，不群发旧重置记录。正文每轮最多补全 6 条，初次历史需要多轮逐步补全；不应通过反复快速点击消耗免费额度。

在开发者工具打开小程序，确认今日雷达有真实记录，来源更新时间正常，预测显示真实来源概率或“暂无有效预测”。若大陆云环境不能访问某个上游，会明确显示来源失败；本机能访问不代表云环境能访问。

## 5. 配置微信订阅消息

进入微信公众平台的小程序后台，按实际账号类目选择可用的订阅消息模板：重置信号、预测提醒。模板名称、字段和资格由微信后台决定，不能假定每个账号都具备相同模板或长期订阅资格。

示意映射（**字段名必须替换成你实际模板的字段**）：

```json
{
  "reset": {"id":"实际模板ID", "fields":{"thing1":"title","time2":"time","thing3":"summary"}},
  "forecast": {"id":"实际模板ID", "fields":{"thing1":"title","time2":"time","thing3":"summary"}}
}
```

填入两个函数的 `WECHAT_TEMPLATES_JSON`。支持值来源：`title`、`time`、`summary`、`probability`、`type`。不需要把 AppSecret 配进云函数。

## 6. 真机验证后启用定时检查

先在开发者工具上传体验版，管理员/体验者微信打开，主动点击授权。测试拒绝授权、保存阈值、中英文设置、取消并删除记录。确认两个模板实际可用，再启用定时器。

在 **pulseSync** 的触发器配置里创建每 10 分钟一次的定时器，7 位表达式为 `0 */10 * * * * *`。附加消息填上文的 `{"secret":"..."}`；函数从 `Message` 解析。不要把带真实 secret 的定时器配置提交到源码。

10 分钟检查一次约每月 4,320 次定时调用，另外还会消耗数据库、网络与前台调用额度。**这不是零费用保证。**先观察一天资源用量；测试结束可停用定时器。额度有限时可改成 15 分钟检查，代价是提醒延迟增加。前台刷新不等于来源每秒更新。

不要为了验收而把旧历史当成真实新事件群发。可先只用自己的测试身份进行隔离测试；最终保留“接口接受”记录和手机微信服务通知的实际收到证据。没有设备证据就不能称推送已验证。

## 7. 发布前

完成小程序后台针对该账号提出的资料、隐私说明、类目、备案/审核步骤（具体以后台要求为准）。将发送目标从 `trial` 改为 `formal` 仅在正式版本发布后进行。

还需复核依赖审计、实际云来源可达性、免费环境是否允许正式服务、消息字段和真机布局。本项目当前不会替你支付认证费、购买套餐或提交正式发布。

## 可选：以后已有自己的服务器

`backend/.env.example` 是 Node + SQLite 后端配置。真实 AppSecret 只存服务端 `.env`；微信端改用完整 HTTPS `/api` 地址，并在微信后台配置合法域名。`Dockerfile` / Compose / Caddy 提供自动 TLS 和持久化卷的配置，但本机未实际运行 Docker。此路径不属于目前建议的免费起步方式。
